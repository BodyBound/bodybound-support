AI Pre-Scan — v3 Variance Test

Each reference generated 4 times at temperature=0: two runs with the pre-scan constraint block, two runs without. Lower variance = more repeatable output. Method: mean absolute per-pixel difference (0–255) between the two runs in each condition.

What pre-scan is in v3: a pure NEGATIVE-CONSTRAINT block — no classification step, no category rules, no stylistic guidance. Only a list of things the model is forbidden to do (change count, pose, framing, identity; introduce new solid black regions; soften/blur edges; override the base prompt). No instruction about how to draw anything.

New controls added: /api/ai-stencil now accepts an optional temperature field (0.0 = most deterministic). This test runs everything at temperature=0.
RESULT — pre-scan does not improve consistency.
Variance with pre-scan is HIGHER than without for both reference images, even at temperature=0. The added constraint tokens act as a weak prompt modifier and introduce more interpretation surface, not less. Per the agreed success criterion — "if constraints cannot be enforced reliably, disable pre-scan temporarily" — recommendation is to keep pre-scan OFF in the production pipeline.
